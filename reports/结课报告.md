## 一、题目

**题目名称**：基于 Docker + docker-compose 构建一个 Web 站点（胡杨好物 · 校园闲置交易平台），并设计一个可解的 CTF-Web 文件上传漏洞靶场。

**要求达成情况**：

1. 实践部署：站点通过 `IP + 端口（26112）` 可达，Compose 端口映射为 `26112:80`；
2. 报告提交：提供网站功能介绍与 CTF 解题步骤报告（见本报告第五节与附件《CTF解题步骤报告.md》）。

## 二、总体架构设计

### 2.1 架构总览

整个系统为单容器架构：宿主机（Windows + Docker Desktop）上的 Docker 引擎运行一个基于 `php:8.2-apache` 官方镜像构建的 Web 容器，通过 Compose 将宿主机 `26112` 端口映射到容器 `80` 端口。用户浏览器（或 CTF 攻击端）访问 `http://<宿主机IP>:26112` 即可使用网站功能。

```
                 ┌─────────────────────────────────────────────────┐
                 │          Windows 宿主机（Docker Desktop）          │
                 │                                                 │
 浏览器 / CTF ───┼──▶  http://<IP>:26112  ══ 端口映射 26112:80 ══▶  │
 攻击端          │                                          ┌──────┴──────┐
                 │                                          │   web 容器   │
                 │                                          │ php:8.2-apache
                 │                                          │  ┌───────────┐
                 │                                          │  │ Apache2:80 │
                 │                                          │  │ PHP 8.2    │
                 │                                          │  │ Session    │
                 │                                          │  └───────────┘
                 │                                          │ /var/www/html/  ← src/ 整站源码
                 │                                          │   ├─ index.php（商品广场 + hint）
                 │                                          │   ├─ login.php / dashboard.php
                 │                                          │   ├─ favorites.php / cart.php
                 │                                          │   ├─ profile.php（资料编辑）
                 │                                          │   ├─ upload.php（上传漏洞点）
                 │                                          │   ├─ flag_submit.php（flag 校验）
                 │                                          │   ├─ data/profile.json（资料持久化）
                 │                                          │   └─ uploads/（可写，允许 PHP 执行）
                 │                                          │ /flag  ← flag 文件（Web 根目录之外）
                 │                                          └─────────────┘
                 └─────────────────────────────────────────────────┘
```

### 2.2 技术选型

| 组件 | 选型 | 说明 |
|------|------|------|
| 基础镜像 | `php:8.2-apache` | 官方镜像，自带 Apache2 + PHP 8.2 模块，`.php` 文件全局可执行 |
| Web 服务 | Apache2 | 由基础镜像内置，监听容器 80 端口 |
| 会话管理 | PHP Session | 登录态、购物车、收藏由 `$_SESSION` 维持 |
| 资料持久化 | JSON 文件（`data/profile.json`） | 用户昵称/性别/年龄/生日/地址，www-data 可写 |
| 站点主题 | 胡杨好物 · 校园闲置交易平台 | 普通用户站点外观（暗色玻璃拟态 + 颗粒噪点 UI），掩盖上传漏洞入口 |
| 漏洞设计 | 文件上传"基本类型防护"弱校验 | 仅校验 `Content-Type` 前缀 + 黑名单拦截 `exe/bat/sh/cmd`，可被 MIME 伪造绕过 |
| Flag 存储 | 容器 `/flag`（644） | 位于 Web 根目录之外，前端页面源码不可见 |

### 2.3 漏洞设计思路（CTF 靶场核心）

1. `upload.php` 实现两道"基本类型防护"：
   - 校验 1：`$_FILES['avatar']['type']` 必须以 `image/` 开头 —— 该值来自客户端请求头，**可伪造**；
   - 校验 2：扩展名黑名单仅拦截 `exe / bat / sh / cmd` —— **不拦截 `php`**；
2. 上传文件**不检查内容、不重命名**，以原文件名保存到 `/var/www/html/uploads/`，且该目录保留 PHP 执行能力；
3. 攻击者将一句话木马保存为 `shell.php`，伪造 `Content-Type: image/png` 即可绕过校验，随后通过 `?cmd=cat /flag` 读取 flag；
4. flag 提交校验页面 `flag_submit.php` 在服务端读取 `/flag` 并使用 `hash_equals()` 进行恒时比较，全程不向前端输出真实 flag；
5. 主页源码中埋有开发注释 hint（不含 flag 值），用于引导解题。

## 三、Docker 相关配置文件说明

### 3.1 `Dockerfile`

| 指令 | 作用 |
|------|------|
| `FROM php:8.2-apache` | 以官方 PHP 8.2 + Apache 镜像为基础 |
| `RUN printf "%s\n" "flag{...}" > /flag && chmod 644 /flag` | 构建期创建 flag 文件于容器根目录 `/flag`（Web 根目录之外）；使用双引号包裹，规避 flag 值中单引号的转义问题 |
| `COPY src/ /var/www/html/` | 将整站源码复制到 Apache Web 根目录 |
| `RUN mkdir -p /var/www/html/uploads /var/www/html/data && chown -R www-data:www-data ... && chmod -R 775 ...` | 授予 `uploads/` 与 `data/` 目录写权限；`uploads/` **不部署任何禁止 PHP 执行的 `.htaccess`**，保留 PHP 执行能力（漏洞前提）；`data/` 用于用户资料 JSON 持久化 |
| `EXPOSE 80` | 声明容器监听端口 |

### 3.2 `docker-compose.yml`

| 配置项 | 值 | 说明 |
|--------|-----|------|
| `services.web.build` | context `.` / Dockerfile | 使用本项目 Dockerfile 构建 |
| `container_name` | `ctf-bigwork-web` | 固定容器名，便于管理 |
| `ports` | `["26112:80"]` | 宿主机 26112 端口映射到容器 80 端口 |
| `restart` | `unless-stopped` | 容器异常退出或宿主机重启后自动拉起 |

## 四、部署操作步骤

> 前置条件：宿主机已安装 Docker Desktop（或 Docker Engine + docker compose 插件），完整依赖安装说明见项目根目录《README.md》。

```bash
# 1. 进入项目目录
cd bigwork

# 2. 构建镜像（首次部署可直接 build；完整重建用 --no-cache）
docker compose build

# 3. 启动服务（后台运行）
docker compose up -d

# 4. 查看服务状态
docker compose ps

# 5. 浏览器访问
#    http://127.0.0.1:26112      （本机）
#    http://<本机局域网IP>:26112  （局域网其他机器）
```

停止与清理：

```bash
docker compose down        # 停止并移除容器
docker compose down -v     # 同时清除匿名卷
```

一键自动化验证（可选）：

```bash
bash scripts/verify.sh     # 自动重建、启动并完成 13 大项验证，结果见 reports/verify.log
```

## 五、功能介绍（网站功能介绍 / CTF 解题步骤）

### 5.1 网站功能介绍

站点为「胡杨好物」校园闲置交易平台（暗色玻璃拟态 + 颗粒噪点视觉风格），模拟普通校园用户站点：

| 功能 | 路由 | 说明 |
|------|------|------|
| 首页 | `/index.php` | 平台介绍 + 14 件好物商品卡片（分类/价格/成色/简介）；每件商品支持一键**收藏**与**加购**；源码中隐藏上传漏洞 hint 注释 |
| 收藏 | `/favorites.php` | 需登录；收藏/取消收藏（toggle），支持从收藏页直接加购 |
| 购物车 | `/cart.php` | 需登录；数量增减、单件删除、清空、自动合计金额（PRG 模式防重复提交），导航栏含数量角标 |
| 登录 | `/login.php` | 用户名默认预填 `admin`，弱口令 `123456`；失败提示"用户名或密码错误"，成功 302 跳转个人中心 |
| 个人中心 | `/dashboard.php` | 需登录；展示头像、资料摘要、Flag 挑战入口，并提供头像上传表单（`accept="image/*"`）—— 上传漏洞入口 |
| 个人资料 | `/profile.php` | 需登录；编辑**用户名（昵称）/性别/年龄/生日/地址**五个字段，服务端校验 + JSON 文件持久化，昵称同步显示于导航栏 |
| 头像上传 | `/upload.php` | 需登录；两道基本类型防护（见 2.3 节），原文件名保存至 `/uploads/` |
| 提交 Flag | `/flag_submit.php` | 需登录；服务端读取 `/flag` 并以 `hash_equals()` 校验，正确/错误分别提示，源码不泄露 flag |
| 退出 | `/logout.php` | 销毁会话并跳回首页 |

### 5.2 CTF 解题步骤（简述）

1. **信息收集**：查看主页源代码，发现 hint 注释 —— 上传校验只拦 `exe/bat/sh/cmd`，`php/png/jpg` 不过滤且保留原文件名存于 `/uploads/`；
2. **登录**：使用 `admin / 123456` 登录进入个人中心；
3. **制作木马**：本地构造一句话木马 `shell.php`（内容 `<?php @system($_GET['cmd']);`）；
4. **绕过上传**：抓包将上传请求的 `Content-Type` 改为 `image/png`（绕过 MIME 校验），`.php` 不在黑名单（绕过扩展名校验），上传成功且保留原文件名；
5. **GetFlag**：访问 `http://<IP>:26112/uploads/shell.php?cmd=cat%20/flag` 获得 flag；
6. **提交验证**：在"提交 Flag"页面输入 flag，服务端 `hash_equals` 校验通过。

> 完整图文版解题过程、漏洞成因与修复建议见附件《CTF解题步骤报告.md》。

### 5.3 自动化验证结果

`scripts/verify.sh` 自动完成 13 大项验证（服务重建启动、品牌/作者/商品、hint、登录、购物车、收藏、资料修改、exe 拦截、上传绕过 GetFlag、flag 提交、全站源码无泄露、`/flag` 位置、本机 IP 可达），逐项 PASS/FAIL 结果见 `reports/verify.log`。本次部署验证结论：**全部通过（PASS=43，FAIL=0）**。
